# پنل آپلود فایل (PHP)

یک پنل آپلود سبک و کامل با **PHP خالص** (بدون هیچ کتابخانه‌ی بیرونی) که با آن می‌توانی فایل‌های
**تا ۲ گیگابایت** را آپلود کنی و بلافاصله **لینک دانلود** بگیری.

رابط کاربری فارسی و راست‌به‌چپ، با انیمیشن‌های روان (بدون فریم‌ورک جاوااسکریپت)، تم تاریک/روشن،
کشیدن‌و‌رها کردن فایل، آپلود تکه‌تکه با امکان **توقف/ادامه**، نمایش سرعت و زمان باقی‌مانده.

## امکانات

**آپلود**

- سقف حجم هر فایل: **۲ گیگابایت** (قابل تغییر در `inc/config.php`)
- آپلود **تکه‌تکه (chunked)**؛ روی هاست‌هایی که `post_max_size` کوچک دارند هم فایل بزرگ آپلود می‌شود
- **قابل ادامه**: اگر اینترنت قطع شود یا صفحه رفرش شود، همان فایل را دوباره انتخاب کن؛ از محل قطع ادامه می‌دهد
- توقف / ادامه / لغو برای هر فایل و برای همه‌ی فایل‌ها
- تلاش دوباره‌ی خودکار با تأخیر فزاینده + کوچک‌کردن خودکار اندازه‌ی تکه در صورت رد شدن توسط سرور
- چند فایل هم‌زمان، انتخاب پوشه، و آپلود با **Ctrl+V** (فایل‌های کپی‌شده)
- نمایش سرعت، درصد، زمان باقی‌مانده و حجم کل

**لینک‌ها**

- لینک کوتاه و مستقیم: `https://example.com/d/ab12cd34`
- صفحه‌ی اختصاصی هر فایل با پیش‌نمایش (عکس، ویدیو، صدا، PDF) و دکمه‌ی کپی لینک: `/f/ab12cd34`
- پشتیبانی از **Range** (دانلود تکه‌ای/ادامه‌ی دانلود ویدیو)، `ETag` و کش یک‌ساله
- دانلود با نام اصلی فایل (پشتیبانی کامل از نام فارسی)

**رابط کاربری**

- طراحی شیشه‌ای (glassmorphism) با پس‌زمینه‌ی متحرک، انیمیشن‌های ریز و کانفتی پایان آپلود
- تم تاریک/روشن (ذخیره در مرورگر)، فونت وزیرمتن (به‌صورت محلی)، کاملاً واکنش‌گرا و RTL
- اعلان‌های (Toast) زیبا برای هر رخداد
- بدون جاوااسکریپت هم کار می‌کند (فرم پشتیبان روی `/api/upload-simple.php`)

**مدیریت و امنیت**

- حذف فایل با **کلید مخفی** (فقط کسی که فایل را آپلود کرده می‌تواند حذف کند)
- فایل‌ها با **نام تصادفی** ذخیره می‌شوند؛ پسوندهای خطرناک (php, phtml, cgi, sh, ...) با `.bin` ذخیره می‌شوند
- دسترسی مستقیم به پوشه‌ی `storage` بسته است و هیچ فایلی اجرا نمی‌شود
- فایل‌های HTML/SVG به‌صورت `application/octet-stream` و با هدر `nosniff` ارسال می‌شوند (ضد XSS)
- محدودیت نرخ آپلود در ساعت، سقف فضای مصرفی، سقف تعداد فایل‌ها، پاک‌سازی خودکار تکه‌های نیمه‌کاره
- لاگ رخدادها در `storage/data/app.log`

## نصب

فقط PHP لازم است (نسخه‌ی ۷.۴ به بالا؛ پیشنهاد: ۸.۰+). هیچ دیتابیسی، Composer یا کتابخانه‌ای نیاز نیست.

### ۱) هاست اشتراکی (cPanel / DirectAdmin)

1. همه‌ی فایل‌ها را در `public_html` (یا یک زیرپوشه) آپلود کن.
2. مطمئن شو پوشه‌ی `storage` **قابل نوشتن** است (سطح دسترسی ۷۵۵ یا ۷۷۵).
   اگر ساخته نشده بود، پنل خودش می‌سازد.
3. تمام. آدرس سایت را باز کن؛ پنل آماده است.

فایل‌های `.htaccess` و `.user.ini` همراه پروژه هستند و محدودیت‌های آپلود را خودکار تنظیم می‌کنند
(اگر هاست اجازه ندهد، پنل خودش را با محدودیت واقعی سرور هماهنگ می‌کند و تکه‌تکه آپلود می‌کند).

### ۲) VPS / سرور اختصاصی با Nginx

```nginx
server {
    listen 80;
    server_name example.com;
    root /var/www/upload;
    index index.php;

    client_max_body_size 2048M;   # مهم برای فایل‌های بزرگ
    client_body_timeout 3600s;

    location / {
        try_files $uri $uri/ /index.php?$query_string;
        # لینک‌های کوتاه
        rewrite ^/d/([a-zA-Z0-9]+)/?$ /download.php?id=$1 last;
        rewrite ^/f/([a-zA-Z0-9]+)/?$ /file.php?id=$1 last;
    }

    # هسته و داده‌ها نباید از وب قابل دسترسی باشند
    location ~ ^/(inc|storage)/ { deny all; }

    location ~ \.php$ {
        include fastcgi_params;
        fastcgi_pass unix:/run/php/php8.2-fpm.sock;
        fastcgi_param SCRIPT_FILENAME $document_root$fastcgi_script_name;
        fastcgi_read_timeout 3600;
    }

    location ~* \.(css|js|woff2|png|jpg|svg)$ { expires 30d; access_log off; }
}
```

### ۳) اجرای سریع برای تست (سرور توکار PHP)

```bash
php -S 0.0.0.0:8080 router.php
```

سپس `http://localhost:8080` را باز کن. (`router.php` برای لینک‌های کوتاه `/d/...` و `/f/...` است.)

> اگر پنل را داخل یک **زیرپوشه** می‌گذاری (مثلاً `example.com/upload`)، در `.htaccess`
> خط `RewriteBase /upload/` را از حالت کامنت در بیاور و لینک‌ها را چک کن. آدرس‌ها به‌صورت
> خودکار از روی درخواست ساخته می‌شوند؛ اگر لازم شد مقدار `base_url` را در `inc/config.php` دستی بگذار.

## فعال‌کردن آپلود ۲ گیگابایتی

پنل آپلود **تکه‌تکه** استفاده می‌کند؛ یعنی حتی اگر `post_max_size` سرور ۸ مگابایت باشد،
هم می‌توانی فایل ۲ گیگابایتی بفرستی (فایل در تکه‌های کوچک ارسال و روی سرور به هم چسبانده می‌شود).
با این حال برای بهترین کارایی، این مقادیر را بالا ببر:

**php.ini**

```ini
upload_max_filesize = 2048M
post_max_size       = 2048M
memory_limit        = 512M
max_execution_time  = 3600
max_input_time      = 3600
max_file_uploads    = 100
```

یا در آپاچی (mod_php) داخل `.htaccess` و در PHP-FPM داخل `.user.ini` — هر دو در این پروژه آماده‌اند.

در Nginx هم `client_max_body_size 2048M;` را فراموش نکن.

> اگر پشت **Cloudflare** هستی، آپلود مستقیم حداکثر ۱۰۰ مگابایت است (پلن رایگان)؛
> برای فایل بزرگ یا از حالت chunked استفاده کن (همین پنل این کار را می‌کند) یا رکورد را
> روی DNS مستقیم بگذار (ابر نارنجی خاموش).

## تنظیمات

همه‌ی تنظیمات در یک فایل است: **`inc/config.php`**

| کلید | پیش‌فرض | توضیح |
|---|---|---|
| `site_title` | پنل آپلود فایل | عنوان پنل و متن هدر |
| `max_file_size` | ۲ گیگابایت | سقف حجم هر فایل (بایت) |
| `chunk_size` | ۸ مگابایت | اندازه‌ی هر تکه (خودکار با `post_max_size` هماهنگ می‌شود) |
| `max_files_per_batch` | ۵۰ | حداکثر تعداد فایل در هر بار |
| `max_storage_bytes` | ۰ | سقف کل فضای ذخیره‌سازی (۰ = بی‌نهایت) |
| `max_uploads_per_ip_per_hour` | ۲۰۰ | محدودیت نرخ آپلود برای هر آی‌پی (۰ = خاموش) |
| `session_ttl` | ۲۴ ساعت | عمر تکه‌های نیمه‌کاره |
| `allow_delete` | true | اجازه‌ی حذف فایل با کلید مخفی |
| `blocked_extensions` | php, phtml, sh, ... | این پسوندها با `.bin` ذخیره می‌شوند |
| `denied_extensions` | `[]` | این پسوندها کاملاً رد می‌شوند |
| `inline_mimes` | عکس/ویدیو/صدا/PDF | انواعی که داخل مرورگر نمایش داده می‌شوند |
| `base_url` | خالی | آدرس پایه برای ساخت لینک (خالی = تشخیص خودکار) |
| `pretty_urls` | true | لینک‌های کوتاه `/d/xxxx` (نیاز به mod_rewrite یا router.php) |
| `storage_dir` | خالی | محل ذخیره‌سازی (پیش‌فرض: پوشه‌ی `storage`) |
| `hash_max_bytes` | ۶۴ مگابایت | محاسبه‌ی MD5 برای فایل‌های کوچک‌تر |
| `accent`, `accent2`, `accent3` | بنفش/آبی/صورتی | رنگ‌های پنل |
| `default_theme` | dark | تم پیش‌فرض (`dark` یا `light`) |
| `show_recent` | true | نمایش «فایل‌های اخیر» |
| `enable_log` | true | ثبت رخدادها در `storage/data/app.log` |

برای تغییر محل ذخیره‌سازی می‌توانی از متغیر محیطی هم استفاده کنی:

```bash
APP_STORAGE_DIR=/mnt/bigdisk/uploads php -S 0.0.0.0:8080 router.php
```

## ساختار فایل‌ها

```
.
├── index.php               پنل اصلی (رابط کاربری)
├── file.php                صفحه‌ی اختصاصی هر فایل
├── download.php            ارسال فایل با پشتیبانی Range
├── router.php              روتر برای سرور توکار PHP / لینک‌های کوتاه
├── .htaccess               قواعد آپاچی + محدودیت‌های آپلود
├── .user.ini               محدودیت‌های آپلود برای PHP-FPM
├── inc/
│   ├── bootstrap.php       هسته: ذخیره‌سازی، ابزارها، امنیت
│   └── config.php          ← تنها فایلی که برای تنظیمات لازم است
├── api/
│   ├── status.php          محدودیت‌ها و وضعیت سرور
│   ├── init.php            شروع/ادامه‌ی آپلود تکه‌تکه
│   ├── chunk.php           دریافت یک تکه (بدون مصرف حافظه)
│   ├── finish.php          چسباندن تکه‌ها + ساخت لینک
│   ├── abort.php           لغو و پاک‌سازی تکه‌ها
│   ├── list.php            فهرست فایل‌های اخیر
│   ├── delete.php          حذف با کلید مخفی
│   └── upload-simple.php   آپلود معمولی (بدون جاوااسکریپت)
├── assets/
│   ├── style.css           استایل و انیمیشن‌ها
│   ├── app.js              منطق آپلود سمت مرورگر
│   └── fonts/              فونت وزیرمتن (woff2)
└── storage/                (قابل نوشتن) — با .htaccess مسدود شده
    ├── files/              فایل‌های آپلودشده با نام تصادفی
    ├── tmp/                تکه‌های نیمه‌کاره
    └── data/               files.json (فهرست فایل‌ها) و app.log
```

فهرست فایل‌ها در `storage/data/files.json` نگه‌داری می‌شود (با قفل فایل، بدون نیاز به دیتابیس).
اگر تعداد فایل‌ها از ۵۰۰ بیشتر شود، قدیمی‌ترها از فهرست حذف می‌شوند (فایل‌شان روی دیسک می‌ماند).

## رابط برنامه‌نویسی (API)

همه‌ی پاسخ‌ها JSON هستند و `ok` در آن‌ها وضعیت را نشان می‌دهد.

| متد | مسیر | توضیح |
|---|---|---|
| GET | `/api/status.php` | محدودیت‌ها، فضای مصرفی، نسخه‌ی PHP |
| POST | `/api/init.php` | `{name,size,mime,fingerprint}` → `{upload_id, chunk_size, chunks, resume_from}` |
| POST | `/api/chunk.php?u=ID&i=N` | بدنه‌ی خام (octet-stream) = تکه‌ی N |
| POST | `/api/finish.php` | `{upload_id}` → مشخصات فایل + لینک‌ها |
| POST | `/api/abort.php` | `{upload_id}` → پاک‌کردن تکه‌ها |
| GET | `/api/list.php?limit=12` | فهرست فایل‌های اخیر |
| POST | `/api/delete.php` | `{id,key}` → حذف فایل |
| POST | `/api/upload-simple.php` | multipart با فیلد `file[]` (بدون تکه‌تکه) |
| GET | `/download.php?id=ID` | دانلود (`&dl=1` اجبار دانلود، `&view=1` نمایش در مرورگر) |
| GET | `/d/ID` و `/f/ID` | لینک کوتاه دانلود و صفحه‌ی فایل |

نمونه‌ی آپلود با `curl`:

```bash
# ۱) شروع
curl -X POST -H 'Content-Type: application/json' \
  -d '{"name":"movie.mp4","size":10485760,"fingerprint":"abc"}' \
  https://example.com/api/init.php

# ۲) ارسال تکه‌ها (i = شماره‌ی تکه)
curl -X POST --data-binary @part0.bin \
  'https://example.com/api/chunk.php?u=UPLOAD_ID&i=0'

# ۳) نهایی‌سازی و گرفتن لینک
curl -X POST -H 'Content-Type: application/json' \
  -d '{"upload_id":"UPLOAD_ID"}' https://example.com/api/finish.php
```

## امنیت

- **حذف با کلید مخفی**: هر فایل یک `delete_key` تصادفی دارد که فقط به آپلودکننده برگردانده می‌شود؛
  کلیدها در مرورگر (localStorage) ذخیره می‌شوند تا در «فایل‌های اخیر» دکمه‌ی حذف ظاهر شود.
- **اجرا نشدن فایل‌های آپلودی**: فایل‌ها با نام تصادفی ذخیره می‌شوند، پسوندهای خطرناک به `.bin`
  تبدیل می‌شوند، پوشه‌ی `storage` با `.htaccess` و `Require all denied` مسدود است و
  `download.php` فایل را فقط می‌خواند و می‌فرستد (هرگز include نمی‌کند).
- **ضد XSS در نمایش**: فقط عکس/ویدیو/صدا/PDF به‌صورت inline نمایش داده می‌شوند، آن هم با
  `X-Content-Type-Options: nosniff` و `Content-Security-Policy: default-src none; sandbox`.
  فایل‌های HTML، SVG، JS و PHP همیشه با `application/octet-stream` و `attachment` فرستاده می‌شوند.
- **جلوگیری از پیمایش مسیر**: شناسه‌ها فقط `[a-z0-9]` و نام فایل‌ها پاک‌سازی می‌شوند.
- **محدودیت نرخ و فضا**: برای جلوگیری از پر شدن دیسک، `max_uploads_per_ip_per_hour` و
  `max_storage_bytes` را در `inc/config.php` تنظیم کن.

> این پنل عمداً بدون سیستم ورود/احراز هویت نوشته شده است (همان‌طور که خواسته شده).
> اگر می‌خواهی روی دامنه‌ی عمومی باشد، پیشنهاد می‌شود با یک `.htpasswd` ساده یا
> محدودیت IP، دسترسی به پنل را محدود کنی. خود فایل‌ها با کلید مخفی حذف می‌شوند و
> کسی بدون داشتن لینک آن‌ها را پیدا نمی‌کند.

## بررسی صحت (تست‌شده)

این سناریوها روی نسخه‌ی فعلی به‌صورت واقعی اجرا و بررسی شده‌اند (PHP 8.5):

| سناریو | نتیجه |
|---|---|
| آپلود تکه‌تکه‌ی ۲۰۰ مگابایتی (۲۴ تکه) | فایل نهایی با MD5 یکسان با فایل اصلی ✅ |
| قطع و ادامه‌ی آپلود (نشست با همان اثر انگشت) | ادامه از تکه‌ی نرسیده ✅ |
| توقف و ادامه (Pause/Resume) از سمت مرورگر | بدون خراب شدن فایل ✅ |
| پروکسی سخت‌گیر (رد درخواست‌های بیش از ۲ مگابایت) | پنل خودکار تکه را کوچک کرد و آپلود کامل شد ✅ |
| دانلود با `Range` (ادامه‌ی ویدیو) | پاسخ `۲۰۶` و بایت‌های درست ✅ |
| کش مرورگر (`ETag` / `If-Modified-Since`) | پاسخ `۳۰۴` استاندارد ✅ |
| حجم بیش از ۲ گیگابایت | با پیام روشن رد می‌شود ✅ |
| پسوندهای خطرناک (`php`, `html`, `svg`) | با نام امن ذخیره و اجباراً دانلود می‌شوند ✅ |
| پیمایش مسیر و شناسه‌های نامعتبر | رد می‌شوند ✅ |
| حذف فایل با کلید اشتباه | رد می‌شود (فقط صاحب فایل) ✅ |
| فرم بدون جاوااسکریپت | آپلود + ریدایرکت با پیام ✅ |

> برای اجرای سریع همین تست‌ها روی سرور خودت: یک فایل چند صد مگابایتی را با پنل آپلود کن،
> وسط کار اینترنت را قطع/وصل کن، و بعد از لینک، فایل را دانلود و چک‌سام آن را مقایسه کن.

## عیب‌یابی

| مشکل | راه‌حل |
|---|---|
| خطای ۴۱۳ یا حجم فایل بزرگ رد می‌شود | `post_max_size` و `upload_max_filesize` را در php.ini/.htaccess/.user.ini بالا ببر. پنل خودش تکه‌ها را کوچک می‌کند، اما سرور باید اجازه دهد. |
| «پوشه‌ی موقت قابل نوشتن نیست» | دسترسی پوشه‌ی `storage` را به ۷۵۵/۷۷۵ تغییر بده (`chmod -R 775 storage`). |
| لینک `/d/xxx` کار نمی‌کند (۴۰۴) | `mod_rewrite` را فعال کن یا `pretty_urls` را در `inc/config.php` روی `false` بگذار (آن وقت لینک‌ها `download.php?id=...` می‌شوند). |
| لینک‌ها با دامنه‌ی اشتباه ساخته می‌شوند | مقدار `base_url` را در `inc/config.php` دستی بگذار، مثلاً `'base_url' => 'https://example.com/upload'`. |
| آپلود وسط کار قطع می‌شود | صفحه را رفرش نکن؛ همان فایل را دوباره انتخاب کن. آپلود از محل قطع ادامه می‌یابد. |
| می‌خواهم همه‌ی فایل‌ها را پاک کنم | محتوای `storage/files/` و `storage/data/files.json` را خالی کن. |
